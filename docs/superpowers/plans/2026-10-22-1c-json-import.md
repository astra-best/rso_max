# Импорт вложенной выгрузки 1С в JSON

## Критерии и дизайн

- Админ-страница принимает только `.txt` с UTF-8 JSON-массивом; upload/request body ограничены единым `MAX_CONTENT_LENGTH` (по умолчанию 128 MiB, настраивается окружением). Существующий `database.import_from_excel` остаётся для совместимости со старыми данными.
- JSON читается как `PersonalAccount → MeteringPoints → Meters → Scales → TariffZones`. Внутренние integer PK/FK остаются отдельными от внешних ID 1С.
- Пустые и повторные нормализованные номера ЛС пропускаются. Существующие счета обновляются по `number`; `fio` и `address` не затираются, если этих значений нет в JSON.
- Добавляются сущности точек учёта и приборов, дочерние таблицы шкал/тарифных зон, а также M:N `licschet_metering_points`. Повтор `MeterID` в одной выгрузке отклоняет весь импорт до записи. Импорт атомарен.
- Upsert сохраняет сущности и связи, отсутствующие в новой выгрузке. JSON не добавляет строки в `pokazaniya`. Текущие `schetchiki` и показания сохраняются миграцией и продолжают обслуживаться legacy-путём.
- Предоставленный `docs/ВыгрузкаJSON.txt` содержит повторяющиеся `MeterID` и должен быть отклонён согласно правилу уникальности. Файл не модифицировать и не копировать в тесты.
- Синтетический генератор ограничен максимумом 1000 ЛС; поддерживает негативный режим с повторным `MeterID`. Первый DB-прогон — максимум 100 ЛС; до большего объёма требуется отдельное разрешение владельца.
- Текущий HTTP importer читает максимум 128 MiB и полностью разбирает JSON в памяти; он не подходит для предполагаемых 600 000 ЛС. Линейная оценка sample-файла около 358 MB превышает лимит. Это блокирующее ограничение: до заявлений/использования такого объёма нужны streaming/staging importer, корректная атомарность и отдельный разрешённый volume test. Первую проверку не увеличивать выше 100 ЛС.

## План реализации

1. Тестами зафиксировать атомарный импорт вложенной структуры, внешние ID отдельно от PK/FK, M:N для общей точки учёта, сохранение ФИО/адреса, отсутствие удалений и показаний, откат при повторном `MeterID`, а также сохранность legacy-данных при `init_db`.
2. Добавить аддитивную схему в `database.init_db`, JSON-парсер и импортёр с полной валидацией до `BEGIN IMMEDIATE`; обновить `get_schetchiki`, чтобы runtime видел JSON-приборы вместе с legacy-записями без удаления старых строк.
3. Переключить `/upload` и шаблон на `.txt` JSON, обновить HTTP-тесты для отказа `.xlsx` и успешного/ошибочного JSON.
4. Добавить генератор JSON до 1000 ЛС; проверить синтетический импорт не более чем 100 ЛС и атомарный отказ негативного набора. Перед большим DB-прогоном запросить разрешение владельца.
5. Запустить связанные тесты и статические проверки, доступные в среде; передать стабильный diff координатору для независимого ревью/тестирования.

## Область файлов

- `database.py`: аддитивная схема, атомарный importer, чтение новых приборов.
- `web.py`, `templates/upload.html`: только новый формат админ-загрузки.
- `tests/test_database_1c.py`, `tests/test_main_fixes.py` и/или отдельный `tests/test_1c_json_import.py`: содержательные тесты поведения и формы.
- `scripts/generate_synthetic_1c_json.py`: ограниченный синтетический набор.
